Context interpretation policy for both existing extraction rounds:

Before a final acceptance, review every proposed task's Context together with
its mathematical purpose in this same response. Check three distinct needs:
1. This occurrence's complete conditions, parameters, objects and asserted
   result or construction.
2. The actual standing setting, including applicable global assumptions and
   local section, case and variable scope. A nearby construction does not
   replace this setting; do not import another case's assumptions.
3. The author's definitions and conventions needed to understand this task's
   own goal. If a selected definition uses an author-defined object, statistic
   or comparison convention that determines that goal's meaning, locate that
   directly relevant definition too. A property name or its outer defining
   sentence is insufficient while those ingredients remain unbound.

Reading a source does not attach it to Context. Select every necessary source,
including sources already fully supplied. A context_menu full_text_in alias
refers to the complete row in candidates or paragraphs. Prefer quote:null for
a whole supplied row; use a unique exact literal subquote to separate scopes
or independent tasks. A catalog preview is not a full source read. Use
self_contained:true only when the task's own complete source really supplies
all its needed meaning and setting. Keep premises and conclusions distinct.

For a proof with an implicit goal, select the actual target and its governing
assumptions as interpretation background. A proof fully stating its own goal
and setting needs no invented separate target. This does not establish a
proves edge or check proof validity. Do not recursively complete invoked
theorems' proofs or every cited result's Context, or demand source definitions
for ordinary domain vocabulary. Preserve author omissions and apparent defects
literally; do not supply a mathematical repair.

Request a missing necessary source by its catalog ID or a specific source-only
query before accepting. Use the existing bounded followups of this same round,
not a separate review call. After a followup, return the complete Context with
every still-needed selector, not only newly obtained ones. Recheck its actual
scope instead of mechanically unioning all backgrounds. Explain the source
basis briefly in the existing reason field; add no checklist or certificate
fields and keep the four categories, task granularity and response schema.

If meaning or scope remains genuinely unresolved and no informative source
request remains, return context_requests:[] and uncertain. In round one, mark
the affected candidate uncertain. In round two, use the existing whole-chunk
uncertain disposition with nodes:[]; do not silently omit an unresolved task
under no_supplement or context_only. An uncertain answer is a terminal outcome,
not a reason for an additional review attempt. Never request evaluation
references, scores, expected nodes or an answer inventory.
